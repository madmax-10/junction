# Task 2.3 — Catalog MSRP lookup

## Purpose and actual model

[`get_catalog_reference()`](./catalog_service.py) performs a read-only lookup
against [`vehicles.models.NewCar`](../../vehicles/models.py), whose database
table is `new_cars`. The catalog has UUID `id`, admin `owner`, `make`, `model`,
integer `year`, optional `trim`, nullable `msrp`, and `created_at` fields.
`msrp` is a `DecimalField(max_digits=12, decimal_places=2)`. The model permits
duplicate make/model/year/trim entries; this function does not assume uniqueness.

Inspection found only catalog create/update/delete services and no existing
lookup or executable shared agent response schema. This function therefore uses
a small local dictionary result, consistent with the existing Task 2.2 style.
Task 2.2 was committed in `388f7e4` before this task, with a clean worktree.

## Inputs and validation

```python
get_catalog_reference(make, model, year, trim=None)
```

- `make` and `model`: nonblank strings of at most 100 characters after trimming.
- `year`: a Python integer, not a boolean, float, Decimal, or numeric string.
  The existing shared `validate_model_year()` supplies the allowed range:
  1900 through the current year plus one, matching vehicle serializer policy.
- `trim`: omitted (`None`) or a nonblank string of at most 100 characters.
  Empty strings are invalid, not a request for an arbitrary default variant.

Invalid input raises `ValueError` before querying. The existing DRF validation
exception from the shared year validator is translated into `ValueError` at
this service boundary. No shared validator or model is modified.

## Lookup sequence

1. Validate and trim search inputs.
2. Filter `NewCar` by case-insensitive exact make/model and exact year.
3. If supplied, require a case-insensitive exact trim; do not fall back.
4. Fetch at most two matching rows, projecting only ID and public catalog facts.
   Two rows are sufficient to detect ambiguity without loading the full catalog.
5. No match returns `no_results` and a null reference.
6. More than one match returns `ambiguous` and a null reference. This includes
   different variants without trim and duplicate exact entries even with equal
   prices. A priced row is not preferred over a matching row with missing MSRP.
7. One match with unavailable MSRP returns `insufficient_data`, retaining the
   catalog ID and vehicle facts with null MSRP.
8. One match with finite nonnegative MSRP returns `completed` and the stored
   Decimal, without rounding, averaging, currency conversion, or price adjustment.

No owner/issue lookup, database write, external API, ADK, or LLM is involved.

## Output structure

```python
{
    "status": "completed",  # no_results / ambiguous / insufficient_data otherwise
    "msrp_reference": {
        "catalog_id": "UUID as a string",
        "make": "Toyota",
        "model": "Camry",
        "year": 2024,
        "trim": "SE",
        "msrp": Decimal("30123.45"),
        "price_basis": "catalog_msrp",
    },
    "limitations": [
        # Manufacturer/catalog reference, not used-car value, dealer price or stock.
        # Accuracy/freshness not independently verified; empty-state reason if applicable.
    ],
}
```

`msrp_reference` is `None` for missing or ambiguous matches. For one row with
missing or invalid MSRP, it contains the row identity and null `msrp`. Zero is
valid under the existing catalog model and is not mistaken for missing data.
No private owner details are returned. Decimal serialization belongs to a later
JSON/tool boundary; this task returns Python data.

## Synthetic example and relationship to Tasks 2.1/2.2

The isolated tests insert a **synthetic fixture** for a 2024 Toyota Camry SE
with MSRP `30123.45`. This is not a real manufacturer price claim. A lookup for
`("toyota", "CAMRY", 2024, "se")` returns that exact stored Decimal. If an XLE
fixture also exists and trim is omitted, the lookup returns `ambiguous` rather
than choosing either price. Tests never insert entries into a production catalog.

Task 2.2 searches published Sell posts for used-car asking prices. Task 2.1's
[`estimate()`](./valuation_service.py) calculates their observed range and can
preserve this lookup's `msrp_reference` as separate context. An eventual Agent 2
wrapper can pass `result["msrp_reference"]` to that optional argument. This task
does not wire the functions together, invoke another agent, or alter either task.

MSRP means manufacturer's suggested retail price: it is not a completed sale,
a verified current dealer offer, confirmed availability, or the value of a used
car. It never fills in missing comparable evidence or changes the used-car range.

## Limitations

- Catalog accuracy, authenticity, regional applicability, and freshness are not
  independently verified. No new data or prices are generated by the lookup.
- Currency, options/packages, incentives, dealer inventory, and regional pricing
  are not represented by this model and are not inferred.
- There is no fuzzy matching, nearest-year fallback, default trim, or duplicate
  resolution policy. Ambiguity requires more input or catalog-owner correction.
- The shared year policy also limits historical lookups to its accepted range.
- This is a local service result, not a new shared agent response contract.
