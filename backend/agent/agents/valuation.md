# Vehicle valuation agent

The authenticated ADK tool `calculate_value_range(used_car_id, comparable_ids, tool_context)` checks the shared server-bound identity and delegates to the owner-scoped valuation service. Identity is never a model-supplied argument. An empty comparable ID list requests automatic eligible make/model discovery; explicit IDs restrict evidence. No invented vehicle IDs, search tolerances, prices, or currency are permitted.

The service uses Gemini through the existing AGENT_MODEL/GOOGLE_API_KEY configuration to weight actual eligible database asking-price comparables. A Pydantic response schema and server validation restrict the response to known IDs, finite relevance weights and explanations. The server computes `estimated_value = sum(price * weight) / sum(weight)` with Decimal arithmetic. There is no active median calculation; legacy median is always null. At least three distinct eligible records with positive weights are required. Low/high describe observed evidence, not confidence bounds. MSRP remains a separate reference.

The tool returns the existing JSON-safe status/data/ids/provenance/error envelope. Provider failure, invalid weights or thin evidence cannot produce a successful estimate. These are asking estimates, not calibrated real sales; no currency is inferred. Approval timestamps, synthetic markers and seed mock.local issue owners are checked before evidence reaches the provider. Publication and absent flags cannot prove authenticity.

The factory preserves the shared ValuationReply output schema. Final replies contain agent/status/message; grounded prices remain in tool data and may be described accurately in the message. A completed estimate maps to answer, a missing vehicle ID to needs_input, insufficient evidence/provider failure to unavailable, and tool errors to error. The coordinator remains the user-facing voice.

Focused tests use the configured Python environment and mocked/injected weighting providers. No live Gemini or paid API call is needed. Authentication, ownership privacy, read-only database behavior, discovery, approval/mock exclusions, weighted arithmetic and provider failure are tested. Live provider/model compliance is not verified by these offline tests.
